# Вектор

Ruby 4.0.7, Rails 8.1.4, SQLite, Devise.

## Запуск

```sh
bundle install
bin/rails db:prepare
bin/rails db:seed
bin/rails server
```

`/`, `/index.html` и `/about.html` открыты без авторизации. Главная содержит ссылку «О проекте» и форму сбора email. Регистрация: `/users/sign_up`, вход: `/users/sign_in`.

## Администрирование

`/admin` доступен только пользователям с ролью `admin`. Чтобы назначить эту роль уже зарегистрированному аккаунту, откройте `bin/rails console` и выполните:

```ruby
User.find_by!(email: "your-email@example.com").update!(role: :admin)
```

В меню три раздела:

- Статьи: создание, редактирование и удаление. Автор, категория, текст Markdown, обложка и параметры публикации.
- Категории статей: создание и удаление. Категорию, используемую статьями, удалить нельзя.
- Тесты: создание, редактирование и удаление. Вопросы добавляются и удаляются прямо в форме теста. У каждого вопроса ровно четыре заполненных варианта и один правильный ответ.

Вопросы и ответы сохраняются вместе с тестом в транзакции. Ошибка вложенного вопроса отменяет всю запись. Тест без попыток можно удалить вместе с вопросами и вариантами. После появления попыток нельзя удалить тест, менять структуру или правильность ответов; текстовые опечатки можно исправлять. Для новой редакции создайте новый тест.

Гостевые и пользовательские попытки, серверный подсчёт результата, профиль, комментарии, лайки, подписки на категории и сбор согласий на рассылку сохранены. Публичный интерфейс прохождения тестов пока не создан. Форма на главной сохраняет email в отдельную таблицу `subscribers` только при согласии на обработку данных; отправка писем не подключена. Реальные письма не отправляются.

## Данные

Актуальная схема: `db/schema.rb`. Миграция `20261027010000_remove_admission_and_tags.rb` удаляет исключённые из проекта таблицы; откат удалённых данных не предусмотрен. Миграция `20261027020000_expand_legacy_demo_answers.rb` дополняет старые демонстрационные вопросы до четырёх вариантов, сохраняя правильные ответы и результаты попыток. Исходная миграция сохранена как история базы. Документ `vector-data-model.md` — исходное задание, он не отражает последующее сокращение проекта.

Демонстрационные сиды используют стабильные ключи и не очищают БД. Пароли демо-пользователей случайные. Сиды не назначают администратора.

## Проверки

```sh
bin/rails test
bin/rails zeitwerk:check
bundle exec rubocop --cache false
```

Проверяются регистрация, публичные страницы, доступ к админке, CRUD статей и категорий, вложенное редактирование тестов, ограничения удаления, проверка ответов и гостевых токенов, согласия на рассылку и повторный запуск сидов.

Адреса из формы главной можно посмотреть в `bin/rails console`: `Subscriber.order(created_at: :desc).pluck(:email)`. Адреса нормализуются, проверяются на формат и защищены от дублей уникальным индексом.

Визуал заглушки реализован по Figma, экран `552:965`. Шаблон — `app/views/pages/index.html.erb`, стили — `app/assets/stylesheets/home.css`, общие части — `app/views/shared/_brand.html.erb` и `_footer.html.erb`. Изображения документов и SVG-стрелки сохранены в `app/assets/images/`; шрифты Fyl и Arial Narrow — в `app/assets/fonts/`.

Два чекбокса подписки имеют разные имена: обязательный `consent` и добровольный `marketing_consent`. Время явно данного согласия сохраняется сервером в `subscribers.personal_data_consent_at` и `subscribers.marketing_consent_at`; старым записям согласие задним числом не присваивается. Письма автоматически не отправляются.

Адаптив заглушки: три версии в `home.css`: мобильная до 767px, планшетная 768–1199px, десктопная от 1200px. Размеры рассчитываются через `--unit` в `vw` от макетов шириной 390, 1024 и 1728 соответственно.

В мобильном макете системная строка iPhone относится к интерфейсу телефона и в HTML не воспроизводится. Кнопка «задать вектор поступления» ведёт на главную заглушку; «подать заявку» — в Telegram автора: https://t.me/vaguesorrow. Для страницы не создавались модели или миграции.
